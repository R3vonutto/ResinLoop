# ResinLoop · 日常巡查（AstrBot 插件）

把 [ResinLoop](https://github.com/R3vonutto/ResinLoop) 这个 Windows 桌面版「游戏日常未完成提醒」工具
移植成了 AstrBot 插件：原来靠常驻守护进程 + Bark 推送，现在改成 **机器人到点查一轮，没做完就发消息到群里**。

> 名字里的 *Resin* 就是树脂——原神的树脂、崩铁的开拓力、绝区零的电量、方舟和终末地的理智，
> 每天重置的体力就是「日常」本身。

**严格只读**：只查询、只提醒。不签到、不领奖励、不碰任何游戏数据。

**多人各自独立**：账号按「平台 + 发送者」隔离。群里谁绑的号只有谁能查到，
后绑定的人不会覆盖前一个人，`/日常` 永远返回你自己那份；定时提醒也是一人一条，
默认发到各自的私聊，群里看不到别人的账号状态。见 [多人怎么隔离的](#多人怎么隔离的)。

## 支持的游戏

| 游戏 | 数据源 | 判定项 | 顺带展示 |
| --- | --- | --- | --- |
| 原神 | 米游社实时便笺 | 每日委托 | 原粹树脂、探索派遣 |
| 崩坏：星穹铁道 | 米游社实时便笺 | 每日实训 | 开拓力、模拟宇宙周积分 |
| 绝区零 | 米游社实时便笺 | 每日活跃度 | 电量 |
| 明日方舟 | 森空岛 | 每日任务 | 理智（按恢复时间现算） |
| 终末地 | 森空岛 | 每日活跃度 | 理智 |

「判定项」决定今天算不算做完；「顺带展示」只提示不催促——树脂没花完不等于日常没做。
想反过来把体力也算进完成度，把配置里的 `mihoyo_task_scope` 改成 `full`。

## 装它

### 1. 装插件

```bash
cd <AstrBot>/data/plugins
git clone https://github.com/R3vonutto/ResinLoop.git   # 或直接把这个插件目录丢进去
```

> 插件目录名必须是 `astrbot_plugin_resinloop`。若你从本仓库的 `astrbot_plugin_resinloop/`
> 目录打包上传，直接在 WebUI「插件管理 → 安装插件」里选 zip 即可。

然后在 WebUI 的插件管理里启用，依赖（`requests` / `qrcode` / `pillow`）会自动安装。

### 2. 绑定账号（每人扫自己的）

在**私聊**里（避免二维码刷群）：

```
/日常 登录米游社     # 手机米游社 App 扫码 → 自动写入原神/崩铁/绝区零
/日常 登录森空岛     # 手机森空岛/方舟/终末地 App 扫码 → 自动写入方舟/终末地
```

扫码成功会自动回填游戏 UID、区服和昵称，不用手抄 Cookie。
米游社那条还会顺手绑定设备指纹——这是绕过 5003 风控的关键一步。

**不需要管理员权限**，谁发谁绑，写进的是**他自己**的账号表，不影响别人。
多个人可以同时扫（默认最多 3 个会话并行），二维码文件按人分开，不会互相覆盖。

### 3. 订阅提醒

在要收提醒的群或私聊里发：

```
/日常 订阅
```

之后到了配置里的时间点，有未完成项就会推一条。`/日常 退订` 取消。

订阅是**按人**记的：A 在群 1 订阅、B 在群 2 订阅，两人各收各的。
而且只要你跟机器人私聊过一次，提醒就默认只发私聊（配置项 `push_scope`），
所以共用同一个群时不会把某人的账号状态摊给全群看。

### 4. 调时间

WebUI → 插件配置 → 「每日检查时间点」默认 `08:30`、`20:30`。
错过了（机器人关机、群里没人在线）会在**补发窗口**（默认 180 分钟）内补跑一次。

## 指令

| 指令 | 说明 | 谁能用 |
| --- | --- | --- |
| `/日常` | 检查**你自己的**账号，结果回在当前会话 | 所有人 |
| `/日常 状态` | 你的绑定 / 订阅 / 下次检查时间 | 所有人 |
| `/日常 周报` | 你自己最近 7 天的完成率 | 所有人 |
| `/日常 活动` | 即将结束的活动（按你绑的游戏过滤） | 所有人 |
| `/日常 订阅` / `/日常 退订` | 在当前会话收 / 不收你的提醒 | 所有人 |
| `/日常 登录米游社` | 扫码绑定原神 / 崩铁 / 绝区零 | 所有人 |
| `/日常 登录森空岛` | 扫码绑定明日方舟 / 终末地 | 所有人 |
| `/日常 解绑 [游戏]` | 删除自己的绑定；不带参数则全删 | 所有人 |
| `/日常 测试推送` | 按当前结果给你自己推一条（绕过缓存） | 所有人 |
| `/日常 认领` | 把旧版全局配置里的账号并入自己名下 | 管理员 |
| `/日常 帮助` | 指令一览 | 所有人 |

别名：`/resinloop`、`/resin`、`/树脂`、`/日常巡查`。

另外注册了一个 LLM 工具 `query_game_daily_status`，所以也可以直接问 AI：
「我今天的日常做完了吗」「原神树脂满了没」——它查的是**提问者本人**的账号。

> 重复查有 90 秒缓存、10 秒冷却（可配置），群里好几个人同时问不会把米游社打爆。

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | 开 | 关掉后只有手动 `/日常` 才查 |
| `check_times` | `08:30`,`20:30` | 每天检查的时间点，可多个 |
| `catch_up_minutes` | 180 | 错过时间点的补发窗口；0 = 不补发 |
| `push_scope` | `private_first` | 定时提醒发哪：私聊优先 / 只发订阅会话 / 只发私聊 |
| `query_cache_seconds` | 90 | 同一用户查询缓存，0 = 关闭 |
| `command_cooldown_seconds` | 10 | 同一用户两次检查的最小间隔，0 = 关闭 |
| `max_login_sessions` | 3 | 同时进行的扫码会话上限 |
| `always_notify` | 关 | 全部完成也发一条平安通知 |
| `test_mode` | `auto` | `auto` / `force_alert`（每轮都推）/ `force_silent`（只写日志） |
| `resource_alert_enabled` | 开 | 体力溢出预警总开关 |
| `resource_thresholds` | 见下 | 各游戏阈值，填 0 关闭该游戏 |
| `activity_alert_enabled` | 开 | 活动结束提醒 |
| `activity_alert_days` | 3 | 结束前 N 天开始提醒（1~30） |
| `mihoyo_enabled` | 开 | 米游社风控严重时可临时关掉，只查森空岛系 |
| `mihoyo_device_mode` | `auto` | `auto` / `fp` / `gs`，风控排障用 |
| `mihoyo_task_scope` | `daily` | `daily` 只判委托类；`full` 资源也算完成度 |
| `proxy` | 空 | 米游社请求代理，例如 `http://127.0.0.1:7890` |
| `webhook_enabled` | 关 | 额外推一份到 Webhook（多人时只发脱敏汇总） |
| `webhooks` | 空 | Bark / Server酱 / Qmsg酱 / 飞书 / 钉钉 |
| `push_targets` | 空 | **已废弃**，旧版全局会话，仅 `/日常 认领` 时迁移 |
| `accounts` | 空 | **已废弃**，旧版全局账号，仅 `/日常 认领` 时迁移 |

默认体力阈值：原神树脂 160、崩铁开拓力 240、绝区零电量 200、方舟理智 135、终末地理智 300。
当前值 ≥ 阈值就推一条（复用同一轮查询结果，不额外发请求）。

## 多人怎么隔离的

从「一个人的工具」改成「一群人的机器人」，要切开的其实有三样东西：

| 数据 | 存哪 | 隔离键 |
| --- | --- | --- |
| 账号凭证 | `users.json` 的 `accounts` | `平台:发送者ID` |
| 完成历史（周报） | `history/<用户>.json` | 同上，一人一个文件 |
| 提醒订阅 | `users.json` 的 `targets` | 同上，每人一份会话列表 |

`平台:发送者ID` 是**跨群、跨私聊**的：在 A 群扫码绑定，去 B 群或私聊照样查自己的。
好处是不会出现「同一个群绑了两套号、结果互相覆盖」，也不会因为换群就查不到。

定时检查的流程相应变成：

```
到点 → 遍历所有「有账号 + 有提醒去处」的用户
         ├─ 用这个人的账号查一轮（串行，避免同时打五个接口）
         ├─ 按规则判断要不要提醒
         └─ 发到 他的私聊（默认）/ 他订阅过的会话
```

代价与取舍：

- **接口调用量按人数线性增长**：5 个人 × 5 款游戏 = 25 个请求/轮次。所以加了每用户缓存与冷却，
  多人场景建议 `check_times` 不要设太密；
- **设备指纹仍是全机一份**：相当于「一台手机登录多个米游社账号」，比一机一号更像真实用户但也更敏感，
  真遇到 5003 可以配 `proxy` 或调 `mihoyo_device_mode`；
- **Webhook 是机器人级配置**：只有一个用户时发完整报告（单人体验不变），多人时只发
  「N 人有未完成项」的计数摘要，绝不把某个人的账号明细推到别人手机上。

升级前的旧账号（存在插件配置 `accounts` 里）不会被自动分给某个人——因为分不清是谁的。
管理员发一次 `/日常 认领` 就并入自己名下，同时把旧的历史存档复制过来，然后配置自动清空。

## 它是怎么工作的

```
  配置/账号
      │
      ▼
  查询层 ── 米游社实时便笺 / 森空岛游戏数据（只读 HTTP，并行查 5 款）
      │
      ▼
  判断层 ── 汇总「谁没做完、漏了哪几项、谁查询失败」+ 体力溢出 + 活动倒计时
      │
      ▼
  提醒层 ── 到点按规则决定推不推 → 发到订阅会话（可选再走 Webhook）
```

几种「不能当成未完成」的状态，插件会单独标出来，不会误报催你：

- **查询失败**：凭证/网络问题，只提示不催促，连续两次凭证类失败会单独发一条「凭证可能失效」；
- **数据待更新**：森空岛给的是「上次登录时的快照」，当天没进过游戏就判断不了今日进度；
- **未创建角色**：账号下没有这款游戏的角色，等建号后自动生效。

```
astrbot_plugin_resinloop/

├── _conf_schema.json       WebUI 配置表单
├── requirements.txt        requests / qrcode / pillow
├── logo.png                插件图标
├── .astrbot-plugin/i18n/   中英文案
├── tests/selftest.py       离线自测（塞 AstrBot 桩，不联网）
└── rl/
    ├── data_dir.py         运行时目录（AstrBot 插件数据目录）
    ├── settings.py         插件配置 → 引擎强类型配置
    ├── userstore.py        按用户隔离的账号 / 订阅（users.json）
    ├── user_history.py     按用户隔离的历史存档（history/<用户>.json）
    ├── runner.py           查询 + 判断编排
    ├── pusher.py           会话推送 + Webhook
    ├── scheduler.py        定时检查（含补发）
    ├── login.py            扫码登录（米游社 / 鹰角通行证）
    ├── texts.py            回复文案
    └── vendor/             原仓库 core/ 的原样移植（见下）
```

改完代码想确认没写崩，跑一下自测（不联网、不碰真实数据）：

```bash
cd data/plugins/astrbot_plugin_resinloop
python tests/selftest.py     # 105 项断言，覆盖配置解析/命令分发/调度补发/报告渲染/凭证回写/多人隔离
```

运行时状态都在 `data/plugin_data/astrbot_plugin_resinloop/`：

```
  users.json              每人的账号与订阅（明文凭证，别外发）
  history/<用户>.json     每人的完成历史（周报数据源）
  logs/device_identity.json  设备指纹（全机一份）
  logs/qr_*.png           扫码二维码（按人分文件）
```

整目录删掉等于所有人重新绑定一次，不影响插件本体。

## 与上游的差异

引擎部分（`rl/vendor/`，约 8.7k 行）是从原仓库 `core/` **原样移植**的，只改了两件事：

1. 运行时状态目录从「源码树相对路径」改成 AstrBot 的插件数据目录；
2. 模块间绝对导入改成相对导入，活动日历的账号来源改由插件注入。

业务逻辑（DS 签名、设备指纹、森空岛 HMAC、任务口径、文案）一行未改。

换掉的只有外壳：

| 上游（桌面版） | 本插件 |
| --- | --- |
| 守护进程 + 系统托盘 | 插件内 asyncio 轮询（30 秒）+ 补发窗口 |
| Web 控制台（127.0.0.1:8765） | AstrBot WebUI 配置表单 |
| WebView2 桌面窗口 | 不需要 |
| 终端 ASCII 二维码 | 二维码 PNG 发到聊天 |
| Bark / Server酱 / Qmsg / 飞书 / 钉钉 | 机器人会话（主）+ 同一批 Webhook（可选） |
| 扫码后手填配置 | 自动写回**本人**的账号表 |
| 单机单人 | 按「平台 + 发送者」多人隔离 |

没有搬过来的：系统托盘、开机自启、APK 局域网分发、桌面控制台页面、昵称定时刷新
（扫码时会回填一次昵称，之后改名需要重新扫码或手改「备注昵称」）。

## 常见问题

**提示「provider=mock，尚未绑定账号」**
没绑账号时插件不会用演示数据糊弄你（上游同样拒绝），先扫码绑定。

**米游社返回 5003 / 1034 / 10041**
风控。依次试：① 私聊重扫一次（会重新绑定设备指纹）；② 配置里 `mihoyo_device_mode` 设为 `auto`；
③ 换网络或填 `proxy` 再扫一次（`getFp` 按出口 IP 签发指纹，登录和查询必须同一出口）。

**森空岛的「数据待更新」是什么意思**
森空岛只给「上次登录游戏时的快照」。当天没进过游戏，就判断不了今天做没做，
插件不会拿昨天的数据催你。进游戏刷一下再 `/日常` 即可。

**群友能看到我的账号吗**
看不到。账号存在 `users.json` 里，按「平台 + 发送者」分开；`/日常`、`/日常 状态`、
LLM 工具查询都只读调用者自己那份。定时提醒默认发到各自私聊，不会把某人的进度贴到群里。
唯一的例外是 `push_scope=session_only` 且这个人没私聊过机器人——那时提醒发到他订阅的群，
可以让他私聊发一次 `/日常` 即可切回私聊。

**两个人绑同一个米游社号会互相顶掉吗**
不会，各存各的。但同一账号同时被两人扫码，米游社那边可能出现登录态互踢，建议一人一号。

**升级后我的旧账号去哪了**
还在插件配置的 `accounts` 里，但不再参与查询。管理员发 `/日常 认领` 并入自己名下，
旧的历史存档也会一起复制过去，然后配置自动清空。

**凭证会不会泄露**
凭证存在 `data/plugin_data/astrbot_plugin_resinloop/users.json`（明文）与设备指纹缓存里，
日志与回复都做了打码。但它终究是账号凭证：这个文件别提交、别外发，也尽量别让群友拿到插件数据目录。
